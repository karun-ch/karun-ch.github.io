Ad Creative Engine

A context agent and a deep agent with seven specialist sub-agents turn a campaign brief into rendered images and video, with every decision traceable.

My role
Built the creative console, context agent and integration bridge, the media generation, storage and review-export pipeline, session auth and the EC2 deployment; integrated the team's deep-agent core.

Overview

  • Marketers hand-crafted audience, copy, visual direction and image prompts, and nobody could see why a creative looked the way it did.
  • Built the bridge, media pipeline and review console around a multi-agent core where specialist agents write findings to a shared wiki that compiles into a master prompt.
  • 7 orchestrated sub-agents, hard 150 s / 600 s render caps, and a per-agent trace with every creative.

Problem

Making an on-brand ad creative meant a marketer working out audience, copy, visual direction, channel format and compliance by hand, then rewriting image-model prompts until something usable came out. Nobody could see why a creative looked the way it did, and review was scattered across chat threads that never showed the creative itself.

Solution

A chat console sends briefs to a Python bridge on EC2. A context agent turns the conversation into structured marketing requirements, and a deep agent runs seven specialist sub-agents that read from and write to a shared Agent Wiki. A prompt synthesizer compiles the wiki into a master prompt, rendered by Nano Banana Pro as an image or Veo 3.1 as video. Creatives are stored by content hash, shown next to the agent trace, and exportable to an XLSX sheet for sign-off.

Architecture

  1. A marketer writes a brief in the console, optionally attaching a reference creative; Nginx proxies it to the bridge.
  2. The bridge checks the session; the context agent turns recent chat into structured requirements, with a heuristic fallback.
  3. A metadata agent extracts palette, OCR text, logo and layout signals from the reference image.
  4. The deep agent runs seven specialist sub-agents, each reading and writing findings in the shared Agent Wiki.
  5. A prompt synthesizer compiles the wiki into a master prompt; Nano Banana Pro or Veo 3.1 renders it.
  6. Creatives are stored by content hash, returned with the agent trace and exportable to an XLSX review sheet.

Key decisions

A shared Agent Wiki instead of agent-to-agent chatter

Sub-agents never pass results directly to each other. Each records typed findings in a shared wiki in a fixed order: audience, product truth, message, visual direction, channel, compliance and prompt synthesis. The bridge returns the wiki snapshot with every run, so the console draws a per-agent trace and any creative can be traced back to the decisions behind it.

A stdlib bridge with hard time budgets

The API is Python's ThreadingHTTPServer with only two third-party dependencies. Image and video generation run on daemon threads capped at 150 s and 600 s, just above the media client's own budgets, so a normal generation is never cut off and a stuck provider call is abandoned. Nginx timeouts and body limits match the bridge's limits.

Creatives on disk, not in the browser

A base64 creative is about 750 KB against roughly 5 MB of localStorage, so creatives were lost on reload. They are now written to disk under content-hash filenames, served only to logged-in sessions, with HMAC-signed URLs so a reviewer can open one from the XLSX export without an account.

Degrade gracefully at every layer

The console has a mock mode that runs the whole pipeline in the browser, so the UI shipped and was demoed before the backend existed. The context agent falls back to heuristics without LLM credentials, and the XLSX export never throws. Server-side session auth replaced a client-side password check.
