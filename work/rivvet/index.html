Overview

  • Indian residential projects still go from plot to preliminary structure by hand, and general-purpose LLMs invent clause numbers.
  • Built a two-mode product: a hybrid RAG assistant that answers only from cited IS-code evidence, and a deterministic design pipeline.
  • 685 backend regression tests; every output exports to SVG, DXF, IFC4 and PDF and is flagged for engineer review.

Problem

Small Indian residential projects, such as a 30x40 G+1 home, still go from plot to preliminary structure by hand: a workable room layout, a column grid, member sizes and drawings, each checked against IS 456, IS 875 and IS 1893. General-purpose LLMs invent clause numbers with confidence and cannot be trusted with geometry or loads, so a chatbot is no help for work an engineer has to sign.

Solution

Rivvet splits the work by how far each part can be trusted. Mode A is a hybrid RAG assistant over structural textbooks and IS codes that answers only from retrieved, cited evidence. Mode B is a deterministic design pipeline: a zoned layout engine, a structural grid derived from the room walls, and preliminary IS 456 sizing, exported as SVG, DXF, IFC4 and PDF. The LLM only explains evidence and turns user intent into bounded edits that are validated before use.

Architecture

  1. IS 456, 875 and 1893 PDFs are parsed with PyMuPDF into clause-tagged chunks, embedded locally and stored in Qdrant.
  2. Ask mode: dense and BM25 candidates are fused by rank, re-scored by query intent and deduplicated.
  3. Claude on Bedrock answers only from retrieved passages and clauses, citing pages, or declines when evidence is thin.
  4. Design mode: the plot and room program become a zoned layout, with stairs and wet areas aligned across floors.
  5. A structural grid is derived from the walls; beams, slabs, columns and footings get preliminary IS 456 sizing.
  6. Deterministic exporters produce SVG sheets, a layered DXF, an IFC4 BIM model and a PDF report for engineer review.

Key decisions

The LLM never touches geometry or numbers

Layouts, member sizes and drawing coordinates come only from solvers and code formulas. The model explains retrieved evidence or proposes edits from a bounded Pydantic vocabulary whose JSON schema is passed as the Bedrock tool input, and every response is validated against it; anything malformed is rejected. Each edit passes a rule gate and a geometry gate, with up to two retries that feed cited errors back to the model.

Hybrid retrieval with an evidence floor

Code questions hinge on exact clause numbers that dense embeddings blur, so retrieval fuses local bge-small vectors with BM25 and routes by intent for figures, tables and comparisons. IS-code clauses live in a separate read-only collection merged at the route level, and a minimum-score floor keeps unrelated clauses out. Conflicting sources are shown side by side for review rather than declared a contradiction.

CP-SAT layout engine (v3, in R&D)

The v3 engine, in R&D behind the production zone tiler, models each floor as interval variables under NoOverlap2D. Rooms that must be adjacent are forced to share a wall, forbidden pairs are kept apart, and upper floors inherit the ground floor's stair and shaft spine as a hard constraint. It runs single-threaded with a fixed seed, so the same input always produces the same plan.

Rollback-safe operations on one host

Production runs under systemd behind Nginx with Qdrant in Docker. Deploys go through AWS SSM for an audit trail, and the frontend is swapped in with atomic directory renames. Qdrant is stopped before every storage backup, because a live copy once corrupted its memory-mapped files and both collections had to be rebuilt from the source PDFs.
