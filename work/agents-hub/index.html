Overview

  • An industrial-AI client needed to show prospects how governed plant agents behave, across seven functions, without months of integrations.
  • Built a coordination hub and seven specialist agents with evidence runs, a strict approval state machine and a cross-agent event relay.
  • 8 independently deployable HTTPS services, 39/39 domain tests across four agents, and single sign-on via 60-second signed handoffs.

Problem

An industrial-AI client needed to show prospects, during long sales cycles, how plant agents actually behave: detect an issue, gather evidence, check constraints, recommend an action, stop for human approval and record the result. It had to cover seven plant functions without waiting months for SAP, MES, SCADA or CMMS integrations, and one generic dashboard would not make agent behavior or governance believable.

Solution

One coordination hub and seven independently deployable specialist agents (energy, quality, maintenance, production, engineering, workforce and warehouse), each running its own workflow against a shared plant-disruption scenario. Every agent shows a visible evidence run, ends at a named-role approval gate, keeps an audit trail and posts its governed decision to the hub's event relay. In the pilot the agents are deterministic and rule-based over authored scenario data; the hub's plant briefing is generated by Claude Haiku 4.5 on Bedrock under a strict tool schema, with a rule-built fallback.

Architecture

  1. The reviewer signs in at the hub, and Nginx checks every request against the hub's host-only session.
  2. Opening an agent, the hub posts a signed 60-second handoff and the specialist issues its own session.
  3. The agent's evidence run shows its source and policy checks, then proposes one governed action.
  4. A named role approves or rejects it; wrong roles are refused and every outcome goes to the audit trail.
  5. The agent posts its decision to the hub's ChangeSet relay, updating the cross-agent coordination board.
  6. The hub asks Claude Haiku 4.5 for a schema-bound plant briefing and falls back to rules if the call fails.

Key decisions

The LLM explains; deterministic rules decide

Calculations, hard constraints, approval gates, records and exports all live in deterministic code, so the math is repeatable and auditable. Bedrock is used only for the hub's briefing, via a forced tool under a strict JSON schema at low temperature with a token cap and timeout. Output is validated server-side; any failure returns a rule-built briefing, and the model can never change workflow state.

Eight deployable apps, not one monolith

Each agent has its own package, lockfile, visual identity and health contract, and the agents share no runtime dependency. The hub talks to agents only over HTTP: it polls health, sends deep links that keep the selected record, and receives governed decisions as ChangeSet events.

Human gates as a strict state machine

Each run ends at a named approver role instead of implying the agent can act. The run-state contract lists allowed transitions (working → needs approval → executing → complete, with blocked, refused, stopped and error branches). Approval is impossible before the gate, rejection needs a reason, and completion needs an audit receipt separating local changes from prepared-but-not-sent actions.

Single sign-on without a shared cookie

The hub issues an HttpOnly, Secure host-only session; specialists receive a signed 60-second handoff bound to their hostname, delivered by POST so it never appears in URLs or logs. Nginx auth_request validates every protected request, and the apps listen on loopback only under separate users with systemd sandboxing and checksum-verified releases.
